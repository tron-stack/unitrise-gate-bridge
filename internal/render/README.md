# Adding a vendor renderer

Only against a **sample file from a live customer site**. The process:

1. Get the customer's current working import file (or have the vendor's
   software export one): the exact bytes their gate software successfully
   consumes today, plus the vendor software name + version.
2. Write `internal/render/<vendor>.go` implementing `Renderer`, registered
   under the provider key the server uses (see `stubs` in `render.go`).
3. Add a `testdata/<vendor>/` fixture pair: an input `api.State` JSON and the
   expected output bytes. The unit test must reproduce the customer's file
   byte-for-byte from equivalent state.
4. Ship behind the server-side provider setting; flip the customer's facility
   to the new provider and watch one full cycle (write + consume + gate
   import) WITH the customer on the phone before calling it done.

Field notes (observed from a live storEDGE Gate install, 2026-08-30):

- PTI/Falcon: folder `C:\PTI`, file `UPDATE.DAT`, consume `Ptisend.bat`
  (generated by PTI-MI; its output starts `REM Automatically Generated from
  PTI-MI`). Codes are numeric, 4–10 digits, with time-zone group numbers.
- Poll cadence in the wild is ~5 minutes; a manual "force full update" exists
  for support calls.
